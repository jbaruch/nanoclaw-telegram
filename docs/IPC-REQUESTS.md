# Durable agent request contract

The agent `container/agent-runner/src/ipc-mcp-stdio.ts::writeIpcFile` writes schema-1 message/task JSON. Host `src/ipc.ts::validateIpcRequest` reads it at ingress. Host-private custody schema (`.claimed-v1/owner.json`) versions custody only; each payload independently contains `schema_version: 1`. These components are co-shipped.

Each payload is an object with version 1 and a supported `type`. `message` requires string `chatJid,text`; `react_to_message` requires `chatJid,emoji`. Task requests are `schedule_task` (prompt,schedule_type,schedule_value,targetJid), `pause_task`, `resume_task`, `cancel_task` (taskId), `update_task` (taskId and a changed prompt/script/schedule field), `refresh_groups`, and `register_group` (jid,name,folder,trigger). Required strings are nonempty. The reader validates optional string routing/metadata, nullable script, schedule/context enums, requiresTrigger boolean and containerConfig/mount field types before effects. Timestamp, createdBy/groupFolder, isMain and sender are advisory context, never host authorization or delivery evidence.

Legacy unversioned and unknown/future versions refuse before dispatch. Exact raw bytes remain in host quarantine and are never silently upgraded, replayed or treated as delivered. Unknown in-flight custody stays held across restart. Repair the co-shipped writer/reader and reconcile native effects before owner-approved replay; there is no automatic migration or force control. A supported request still needs actual registered-source and live DB/channel checks. Agent role flags grant no authority. Tool text confirms queueing only; native channel receipts establish delivery.

The message/task discriminator fixes the channel. Existing request byte/custody bounds, immutable snapshots and nofollow/single-link checks remain. Atomic publication flushes the file and both participating directories before acknowledging queueing; uncertain publication failures never retry an effect.

The task-create boundary converts only native primary-key ID conflicts from its single atomic INSERT into input refusal. It never replaces the existing row or chooses a fresh ID for a retry. The conflicting request stays in quarantine, later valid requests can proceed, and unrelated native SQLite/schema/implementation failures still reach the host lifecycle owner.


Host follow-up input is a separate schema-1 contract: `src/group-queue.ts::sendMessage` writes an atomic JSON file under the registered group's `input/`; `container/agent-runner/src/index.ts::drainIpcInput` reads it. Exact fields are `schema_version:1`, `type:"message"`, and nonempty string `text`. This is host-to-agent input, not a channel-delivery receipt. Unsupported, legacy or malformed-shape input stays byte-preserved and is not admitted to the SDK; later compatible input can progress. No automatic migration exists: reconcile retained input with the co-shipped writer/reader before explicit owner repair. Known malformed JSON remains refused by the existing cleanup path; native read failures retain pending files and already-collected valid input. `_close` is the fixed empty control sentinel, not a JSON payload or proof of completed work.
